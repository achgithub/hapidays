Request type is set above (HTTP / GraphQL / SOAP / gRPC). For HTTP, choose how the body is shaped here.

Inserted into <soap:Header> at send time (not stored in the body text) — PasswordDigest is generated fresh per request since it's time-bound (Nonce + Created), so it won't match if you inspect the raw body above.

XML-signs <soap:Body> using the client certificate configured in Settings (the same one used for mutual TLS). Inserts a <ds:Signature> into the WS-Security header at send time.

Request JSON goes in the body editor below (protojson — field names are the message's proto3 field names). Metadata is gRPC metadata, not HTTP headers, so it's kept in its own table.

Imported Postman scripts are shown for reference only — hapidays does not execute JavaScript. Use a Capture rule instead to pull a value out of the response into an environment variable (e.g. the SAP/OData "X-CSRF-Token: Fetch" pattern).

Pass/fail checks evaluated after the response comes back — no JS engine, same reasoning as Captures. Shown against a single Send, and aggregated into a pass/fail count when this request runs as part of a collection run.
